# 声波聊天 · 设计文档

> 本文档是设计的**唯一事实来源**。任何行为变更都应先改这里，再改代码。
> 文档只描述**当前**设计；历史版本见文末「修改历史」。

---

## 1. 核心概念

| 概念 | 含义 | 由谁发起 |
|---|---|---|
| **广播 Broadcast** | 主动发声宣告"我在这里"，**开关式**，持续到配对成功或手动停止 | 想被找到的一方（设备 A） |
| **扫描 Scan** | 主动"检测可连接设备"，**开关式**。只有扫描中，收到的广播才记入列表 | 想找人的一方（设备 B） |
| **连接 Connect** | 从列表选设备 → 输入 A 屏幕上的 4 位 PIN → 发起连接 | B |
| **会话 Conversation** | 以 `peerId` 为键的聊天记录 | — |

**默认完全静默。** 点「开始使用」只开麦克风，不发声。只有点「广播」才会出声。

## 2. 帧类型

| 帧 | 值 | 方向 | 载荷 | 说明 |
|---|---|---|---|---|
| `BEACON` | 0x1 | A → 广播（dst=0） | `nonce(4) + nameLen(1) + name` | 宣告存在。**绝不包含 PIN** |
| `CONNECT_REQ` | 0x2 | B → A | `pin(2, 大端) + nameLen(1) + name` | 请求连接 |
| `CONNECT_ACK` | 0x3 | A → B | `nameLen(1) + name` | 同意连接 |
| `REJECT` | 0x4 | A → B | `reason(1)` | 拒绝。`1=pin错 2=未在广播 3=忙` |
| `MSG` | 0x5 | 双向 | `msgId(2) + chunk(1) + total(1) + data` | 聊天正文 |
| `ACK` | 0x6 | 双向 | `seq(1)` | 停等确认 |
| `BYE` | 0x7 | 双向 | — | 主动断开 |

帧头 6 字节：`ver|type, seq, src, dst, len, crc8`。

**`src == 本机 id` 的帧如何区分"自己的回声"和"对端用了同一个设备 ID"**：
用 `nonce` 精确判定——自己的 `BEACON` 带的是自己的 nonce，对端的必然不同。
不要用"多久没发声"这类时间窗：广播每约 3.8 秒一次，时间窗给宽一点就会把真实的 ID
撞车误判成回声而漏掉。撞车时 **nonce 大的让位**（改 ID 后重新广播）。

## 3. 半双工约束（决定了整个时序设计）

声波是**广播 + 半双工**信道：同一时刻只能一方发声。而本实现里**自己发声期间会丢弃麦克风输入**
（否则会解到自己的声音）。

> ⚠️ **推论：「一直广播」不能理解成「不间断发声」，否则 A 永远听不到 B 的连接请求。**

所以广播必须是**周期性发声 + 静默窗口**：

```
A: [发声 BEACON ~1.2s] → [静默 ~2.8s，只听] → [发声] → [静默] → …
                            ↑
                    B 的 CONNECT_REQ 必须落在这里
```

- 周期 ≈ 4.0 秒（稳健档实测；快速档发声约 0.77s，周期约 3.6s）
- 静默期若侦听到信道忙（对端在发），**跳过本次发声**，避免叠音

## 4. 连接时序

```
【A 侧】
点「开始使用」 → 静默监听
点「广播」     → 生成 4 位 PIN，大字显示在屏幕上
                 开始循环：[BEACON 1.2s] [静默 2.8s]

                 收到 CONNECT_REQ
                   ├ PIN 正确 → 回 CONNECT_ACK → 停止广播 → 配对完成
                   ├ PIN 错误 → 回 REJECT → 错误计数 +1
                   │             满 3 次 → 自动停止广播（防穷举）
                   └ 未在广播 → 回 REJECT(reason=2)

【B 侧】
点「开始使用」 → 静默监听
点「检测设备」 → 进入扫描中
                 收到 BEACON → 列表出现「设备A（信号强）」
选设备 → 输入 PIN → 点「连接」

                 之后 B 借 A 的广播节奏发送请求：
                 每收到一次 A 的 BEACON → 等 0.3~0.7s（随机）→ 发 CONNECT_REQ
                 最多 3 次；期间收到 CONNECT_ACK 即成功

                 收到 CONNECT_ACK → 配对完成，进入会话
                 收到 REJECT(1)   → 提示"数字不对，再试一次"
                 3 次无响应        → 提示"连接失败"
```

**B 为什么"借广播节奏"发请求**：A 的 BEACON 一结束就是它的静默窗口开始，
B 解完 BEACON 的时刻约等于窗口起点。这样**不需要任何时钟同步**，B 天然落在窗口里。

## 5. PIN 设计

| 项 | 规则 |
|---|---|
| 格式 | 4 位十进制，`0000`–`9999` |
| 生成 | 每次点「广播」重新生成；广播期间不变 |
| 作废 | 配对成功 / 手动停止广播 / 错误满 3 次 |
| 显示 | **只在 A 的屏幕上**，大字 |
| 传输 | **绝不进入任何声波帧** ← 整个设计的安全前提 |
| 校验失败 | 回 `REJECT(1)`，计数 +1，满 **3** 次自动停止广播 |
| 用途 | **授权**（证明 B 是从 A 那里线下得知的），**不是加密** |

**安全边界（必须说清）**：

| 威胁 | PIN 能挡吗 |
|---|---|
| 别人乱连你的设备 | ✅ 能 |
| 别人偷听你们聊天的内容 | ❌ 挡不住（声波是广播的，不连接也能听） |

> 4 位数字只有 10000 种可能，同一房间的攻击者发一个约 1 秒的帧就能试一次。
> **不做 3 次上限，PIN 就是摆设。**

## 6. 设备与会话模型

同一时刻**只能有一个活跃连接**（半双工 + 单 peer 状态机）。所以：

- **可连接设备**：扫描发现的，临时（超过 `discoverTtl` 未再收到广播则移除）
- **已知设备**：连接成功过的，持久化在 `sc.peers`，用于列表和历史分组
- 点击设备：
  - 它是当前连接 → 进入会话，可发消息
  - 否则 → 显示历史（若有）+「连接」按钮（需输 PIN）

**明确不做**：同时与多台设备对话。

## 7. 数据存储

| 键 | 位置 | 内容 |
|---|---|---|
| `sc.id` | localStorage | 本机持久设备 ID（1–254） |
| `sc.id.tab` | sessionStorage | ID 撞车让位时的本 tab 临时覆盖 |
| `sc.nonce` | sessionStorage | tab 级随机数，用于撞车裁决（nonce 大的让位） |
| `sc.profile` | localStorage | 传输档位偏好 |
| `sc.peers` | localStorage | `{ "<peerId>": { id, name, lastAt } }` 已知设备 |
| `sc.history` | localStorage | `{ peers: { "<peerId>": [ {k,t,m,a}, … ] } }` 按设备分组的记录 |

- 每个设备最多保留 300 条记录
- 昵称可手动修改；**以 `peerId` 为主键、昵称为显示名**
- **不做历史格式迁移**：检测到旧格式直接丢弃重建

**已知代价**：对方一旦重置浏览器数据 / 换浏览器 / 用无痕模式，`peerId` 就会变，
会话记录会断成"新设备"。这是把 peerId 当主键的固有代价，不做伪造的稳定指纹。

## 8. 界面结构

```
┌──────────────────────────────────────┐
│ [设备]      声波聊天      [广播][日志] │
├──────────────────────────────────────┤
│ 待机  我：设备24  未连接  21.3ms/符号 ▮│
├──────────────────────────────────────┤
│ ● 广播中，把下面这 4 位数念给对方  4826 │  ← 仅广播时出现
│                                  [停止]│
├──────────────────────────────────────┤
│         当前会话的聊天记录             │
├──────────────────────────────────────┤
│ [输入框..................]  [发送]    │
└──────────────────────────────────────┘

[设备] → 底部抽屉
┌──────────────────────────────────────┐
│  设备                    [稳健档][关闭]│
│  ── 可连接设备 ──                     │
│   [ 检测设备 ]                        │
│    设备A   设备 1   信号强     [连接]  │
│  ── 已配对 ──                         │
│    设备B   上次 10:23  在线  [进入][改名][删除]│
│  ── 其他 ──                           │
│   [ 清空全部聊天记录 ]                 │
└──────────────────────────────────────┘

[连接] → PIN 弹窗
┌──────────────────────────────────────┐
│  连接「设备A」                         │
│  请输入对方屏幕上显示的 4 位数字        │
│  [ _ _ _ _ ]                         │
│              [取消]  [连接]           │
└──────────────────────────────────────┘
```

**渲染安全**：设备名来自声波，属于不可信输入，所有渲染走 `textContent`，不用 `innerHTML`。

## 10. 明确不在当前范围

1. **加密**：ECDH + AES-GCM。PIN 可复用为 ECDH 的认证材料（类似蓝牙数字比对），一举两得。
2. **超过 3 台设备**：目前多设备同时响应只靠随机延迟避让，规模上去需要真正的调度。
3. **前向纠错**：目前只有 CRC + 重传，加 Reed-Solomon 可提升噪声下的可靠性。
4. **文件传输**：目前只传文字。

## 修改历史

### v2 — 2026-09-22（当前）

**目标**：让"开始使用"默认静默，连接过程可见、可控、需授权。

| 变化 | 之前 | 现在 |
|---|---|---|
| 启动行为 | 每 5 秒自动广播 `HELLO`，未经同意就占用扬声器 | 只开监听，一声不响 |
| 配对方式 | 点「配对」的黑盒流程，不知道对方是谁 | 显式三态：广播 / 扫描 / 连接 |
| 授权 | 房间里任何人广播一下就能连上 | 需输入 A 屏幕上的 4 位 PIN，错 3 次锁 |
| 会话组织 | 单对端隐式配对，所有聊天混在一条流 | 设备列表 + 按 `peerId` 分会话 |
| 帧类型 | `HELLO / HELLO_ACK / MSG / ACK / NACK / BYE` | `BEACON / CONNECT_REQ / CONNECT_ACK / REJECT / MSG / ACK / BYE` |
| 历史存储 | 扁平数组 `sc.history` | `{ peers: { "<peerId>": [...] } }` |

改动范围：`src/protocol.js`（重写）、`src/store.js`（新增）、
`src/app.js` 与 `web/index.html`（重写）、`src/modem.js`（`FRAME` 枚举）。
不迁移旧数据——v1 从未真正投入使用。

### v1 — 2026-09-21

首个可用版本：连续相位 MFSK 物理层 + 单对端隐式配对会话层 + 浏览器界面。

- **物理层**：16 音 MFSK，前导码二维同步，逐符号 bang-bang 定时跟踪，
  CRC8 保护帧头 + CRC16 保护整帧
- **会话层**：`HELLO`/`HELLO_ACK` 隐式配对，分片重组，停等 ARQ，载波侦听让行
- **配对**：`start()` 后每 5 秒自动广播，收到即配对
- **存储**：设备 ID 在 `localStorage`；会话记录是扁平数组

同期修复（不改设计）：

- 设备身份在 `localStorage` / `sessionStorage` 之间反复，最终定为
  「`localStorage` 持久身份 + `sessionStorage` 临时覆盖 + nonce 裁决撞车」
- 按钮缺 `cursor` / `:hover` / `:focus-visible`；`textarea` 漏在表单样式选择器之外，
  导致底部输入框是白底黑字
